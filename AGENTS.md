# Mikka development

Apply the universal invariants below on every task, then load the matching Tier 1 standard or skill from the branch table before acting.

## Authority and boundaries

- **Three-Tier precedence ([Handbook](docs/engineering/HANDBOOK.md#three-tier-documentation-architecture)):** (1) Alex's explicit decision → (2) Tier 3 CI gates → (3) Tier 1 Living Standards → (4) current `main` → (5) Tier 2 dated ADRs (`docs/design/decisions/`). Keep ADRs immutable (edit only a superseded ADR's top `Status:` header), leave frozen [decisions.md](docs/design/decisions.md) untouched, and ignore dated audits, old screenshots, handoffs, or `publication=none` builds as policy.
- **Repo split ([build-source-of-truth](docs/operations/build-source-of-truth.md)):** Public `aspectly-labs/Mikka` (`alexj11324/Mikka`) is the product engine and official-build root; GitHub Actions builds and Cloudflare deploys. Official builds overlay pinned `mikka-hosted-ui` read-only into ignored `.hosted-ui/` and record both SHAs. Private `mikka-cloud` owns company release policy, secrets, staging, cutover, and rollback; generic product work needs no private access.
- **One UI, zero UI in this repo (`scripts/no-public-ui.test.mjs`):** All Web, Desktop, and iOS (`mobile-next/`) UI, CSS, fonts, hooks, and paid blocks (`BoardUI Pro`, `affectUI`, `beUI Pro`) live in `mikka-hosted-ui`; public builds serve `apps/frontend/src/headless.ts`. Keep one interface across Cloud and self-hosted with one authorized reader/writer per operation, fail closed on missing workbench providers, decouple UI view models from filtered dispatch projections, and cover multi-item catalogue flows with Playwright + PG17 E2E regressions.

## Core engineering invariants

- **Docs and decision gates**: `pnpm docs:check` keeps generated facts, banned claims, `docs/decisions/pending.yaml`, and feature-flag waiter metadata synchronized; use `pnpm docs:generate` after editing sources.

- **Domain & terminology ([glossary](docs/design/glossary.md)):** Run settings belong to an **Environment** (`workspace_environments`), not a Project; Bots are Capy-style Captains without Promote/Demote; creating a task records it only and assigning a Bot wakes it; task states are workspace-defined while Needs you / Waiting are derived run states. Name threads `线程` (never `会话` or "Conversation"; avoid `对话` except `对话框`; group chats are `群聊`; `pnpm i18n:check`). Keep thread root run ID, task ID, and execution run ID distinct (`conversation` in code is the `conversations` table family).
- **No permission approvals ([2026-11-27-1615](docs/design/decisions/2026-11-27-1615-no-permission-approvals.md)):** Agents never ask a human for permission: every route runs with full access (Claude Code `bypassPermissions`, Codex `approvalPolicy: "never"` + `danger-full-access`). Connected apps, plugins and MCP use exactly what was authorized on the provider's site — no second approval, no Allow/Ask/Deny, no "always approve". Never add a permission question, approval card, approval policy or remembered-approval path; questions about *what* to do, logins, and security boundaries (isolation, auth, secrets, paid-source guards) stay.
- **UI reuse, copy & libraries ([design-system](docs/design/design-system.md)):** Reuse primitives (R-90); top products are the authority ([2026-11-27-1409](docs/design/decisions/2026-11-27-1409-top-products-over-paid-blocks.md): ChatGPT / Codex and Claude / Claude Code for chat, composer, approvals, status and errors; Capy for the right rail, tabs, sidebar work tree and task detail; Linear for issue/board semantics), so paid blocks are raw material edited in place in `mikka-hosted-ui` to match the reference, and every UI PR cites its reference per surface. Preserve `components/ui/`, `components/reui/`, and `components/motion/` even when unimported. Cut every word whose removal leaves the screen unchanged (R-40: no sheet/dialog subtitles, paid-block slots included; mark-only `🔒 Secured by Mikka`, state-only status lines). Replies use Markdown across Web, Desktop, and iOS ([OpenUI retired](docs/design/decisions/2026-11-25-remove-openui.md)). Screenshot official builds (`Mikka` + `mikka-hosted-ui`).
- **Local-first & Mac boundary:** Run dev servers, databases, `pnpm build`, `pnpm typecheck`, PG17/daemon suites, and production-build screenshots in cloud Linux (`pnpm local:plan`, `pnpm local:check`, `pnpm local:ready`) or CI — **never on the developer's Mac** (small source-only `node --test` checks are fine). Draft PRs fail closed on required aggregators; treat only checks on the latest Ready head as acceptance evidence.
- **Scripted model acceptance ([2026-11-20-1855](docs/design/decisions/2026-11-20-1855-scripted-model-acceptance.md)):** Keep admission, auth, tools, daemon, and PG17 real, mocking only the LiteLLM HTTP boundary. Never send live model prompts from dev acceptance, CI, local-loop, or nightly jobs.
- **Runtime, error & secret hygiene:** Push live updates via `lib/live/*` and `hooks/use-live-key.tsx` — zero new polling (`scripts/polling-policy.mjs`) and non-increasing `tests/idle-request-budget.json` (`pnpm test:idle-budget`). Preserve error causes (`{ cause: error }`, `CodedError`, localized `RunErrors.*`, log name/code only; `scripts/error-cause-policy.mjs`). Keep secrets in secret managers/workload delivery; never commit, write locally, or print secrets; preserve unrelated changes.
- **Five-tier truth & anti-hardcoding ([five-tier-truth](docs/architecture/five-tier-truth.md)):** Keep T1–T5 separated — zero raw `process.env` outside `lib/env/`, zero hardcoded hosts, model IDs, plan-name branches, or business literals in `messages/*.json`; G1–G6 and semantic lint run at zero baselines.
- **Scope, triage & ship-on:** Make the smallest root-cause fix. Ship finished features enabled (flags only for paid compute/model cost, kill switches, or explicit Alex decisions; migrate schema rather than disabling features). Triage review findings by `occurrence (1–10) × impact (1–10)`: file an issue below `5`, and always fix credible security, auth, tenant-isolation, privacy, credential-exposure, data-loss, or irreversible-side-effect risks.
- **Ownership & merging ([dev-workflow §5](docs/dev-workflow.md#5-ownership-and-merging)):** Each issue has one owner who merges its own PRs once CI is green on the latest head and mergeable, using **normal merge commits only** (no squash, rebase, force push, or direct push to `main`). Batch only atomic dependencies (or `>= 2` ready owner PRs under approved rules). The coordinator merges only its own PRs. If production breaks, fix forward or revert via PR; never delete deployments, revoke shared tokens, edit prod Neon, or create paid resources without Alex.
