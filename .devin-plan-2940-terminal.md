## Security model decision
Review terminals (`lib/coding-workspace/terminal/`) are post-mortem tools: gateway
`execution_fence` (scripts/e2b/terminal-gateway.py:70) holds `machine.lock` and
requires receipt `phase=='idle' && nativeExited==true` — the daemon supervisor
writes that receipt via packages/daemon/src/runs/workspace-control.ts.
For THREAD machines the user owns the box and the app already runs arbitrary
commands (setup_rerun) — concurrent shells add no privilege. So thread tickets
carry `control:'thread'` and the gateway skips lock+receipt for them, while still
binding runId/deviceId. Review tickets keep the fence (default `control:'review'`).
