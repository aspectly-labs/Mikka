## 生产 SLI、覆盖与验收 · #3427

| 层级 | 候选 SLI 与当前读法 |
| --- | --- |
| 用户 HTTP | 按路由、方法及实际发布版本统计终态请求。候选可用性目标为滚动 28 天 ≥99.9% 非 5xx，预算为有效请求数 × 0.1%。非流式延迟单独按路由类别统计，阈值待基线校准。当前使用 [HTTP 状态和权重诊断](https://us.posthog.com/project/670821/insights/qGzT7dJq) 查看观察样本及缺失字段。 |
| SSE | 逐次流式尝试记录首字节时间及终态。上游失败计为失败，有证据的客户端取消单列，未知终态单列。TTFB 目标及终态覆盖待验证。 |
| 任务与队列 | 以唯一任务统计终态失败与投递，以最老待处理任务统计积压年龄，重试按任务归并。需要生产队列计数与终态证据。 |
| 数据库 | 按路由看 RTT 分位数及每个可完整关联请求的查询数，分开检查 N+1。继续使用本页数据库估计和 [供应商传输与心跳](https://us.posthog.com/project/670821/dashboard/2297143)。 |
| 发布与采集 | 使用 [版本与采样覆盖](https://us.posthog.com/project/670821/insights/iOwEnkpu) 对照发布回执。未标记版本、无采集和确认零流量分别处理。 |

全量分母、发布版本或终态覆盖无法对账时，正式 SLO 和预算状态为未知。数据范围与告警回放见 [#3427](https://github.com/aspectly-labs/Mikka/issues/3427)。
